# Reporting — 결과 보고 체계 (비쥬얼라이즈)

결과 보고의 **단일 정답지**입니다. `AGENTS.md` Completion Standard와 `.harness/reporting.json`의 `styleGuide`가 이 문서를 가리킵니다.
프롬프트 계약 테스트(`scripts/tests/run-prompt-contract-tests.ps1`)가 이 문서의 핵심 조항을 검사하므로, 조항을 지우면 CI가 실패합니다.

## 0. 다섯 기둥

1. **항상 비쥬얼라이즈** — 완료 보고의 핵심(변경·검증·리스크)과 `리스크와 다음 판단`·`추천 작업`은 전부 위젯으로 표현합니다. 텍스트는 위젯을 보완할 뿐입니다.
2. **쉬운 말 + 괄호 병기** — 어려운 용어는 일상어로 바꾸고, 남는 변수·코드·스크립트명·전문용어는 **등장하는 자리 우측에 괄호를 열어 쉬운 한글 설명**을 붙입니다(위젯마다 첫 등장은 반드시). 예: `tree hash`(코드 지문), `commit-work-unit.ps1`(커밋 나눠주는 도구), `sendPrompt`(대신 말해주는 비서).
3. **비유 고정** — 모든 보고는 `.harness/reporting.json`의 `analogy`(현재 비유)를 곁들여 설명합니다. **사용자가 바꿔 달라고 명시하기 전까지 같은 비유를 유지**하고, 변경 시에만 `analogy`·`setAt`을 갱신합니다. 세션 시작 훅이 이 값을 매 세션 주입하고, 에이전트 장기 메모리에도 보존합니다.
4. **실행 버튼** — 다음 판단·추천 작업의 모든 안건에 실행 버튼을 답니다(§3). 버튼 없는 안건 나열은 미완성 보고입니다.
5. **정직** — 실측과 가설을 구분 표기하고, 모든 성능·개수 주장 옆에 숫자(가능하면 분모)를 적고, 불리한 결과(불합격·미검증·보류)를 숨기지 않습니다.

## 1. 위젯 골격 (섹션 순서 — 2026-07-22 사용자 선택 확정: 요약 우선 + 펼치기)

```
sr-only h2   : 스크린리더용 한 문장 요약
제목 줄      : 12px muted — 이 위젯이 무엇인지 한 줄
헤드라인     : 큰 결론 한 문장(19px/500, 성패는 색으로 강조: --text-success/danger)
숫자 요약 줄  : 13px 한 줄 — 핵심 수치 2~4개를 " · "로 연결 (실측 표기)
요약 버튼    : 가장 중요한 다음 행동 버튼 1개 (첫 화면에서 결론+행동 완결)
─ 자세히 토글 : "상세 접기/자세히 보기" 버튼 — 아래 상세 영역을 접었다 폄.
              스트리밍 제약상 기본은 펼침 상태로 렌더(숨김 스트리밍 금지), 사용자가 접음.
상세: 카드 그리드 : grid(auto-fit minmax(180px,1fr)) — 항목마다 surface-1 미니 카드,
              카드 안: 아이콘 + 핵심 줄 15px/500, 아래 보조 줄 12px muted (대비형 위계).
              성공 아이콘=--text-success, 경고·보류=#BA7517, 실패=#A32D2D.
              정직 콜아웃도 경고 색 카드로 포함(숨김 금지 — 기본 펼침이므로 노출됨).
결재 버튼들   : 토글 밖(항상 노출) — 안건별 "왜: 안 하면 무슨 일" + 실행 버튼(§3 패턴)
```

- 밀도 규칙(대비형): 결론 19px/500 → 항목 핵심 15px/500 → 보조·근거 12px muted. 13px 장문 문단을 쌓지 않습니다.
- 선택 이력: 전체 구조 C(요약+펼치기)·결론 B(헤드라인형)·상세 B(카드 그리드 — 최초 타임라인 선택을 당일 재조정)·밀도 C(대비형) — 2026-07-22 요소별 견본 비교로 사용자 확정. 변경은 같은 절차(견본 → 선택)로만.

## 2. 언어 규율 (렌더 전 자가 검사)

- [ ] 전문용어가 비유 없이 먼저 나오는 곳이 없는가
- [ ] 변수·코드·스크립트명에 우측 괄호 한글 설명이 붙어 있는가(위젯당 첫 등장 필수)
- [ ] 모든 안건에 "왜(안 하면 무슨 일)"가 붙어 있는가
- [ ] 모든 수치 주장에 숫자와(가능하면) 분모가 있는가, 실측/가설이 구분 표기되는가
- [ ] 불합격·실패·보류가 숨김없이 검사표·콜아웃에 등장하는가
- [ ] 위젯 제목이 맨 위에 한 줄로 있는가

## 3. 실행 버튼 (실측 검증된 패턴 — 2026-07-22)

인라인 `onclick`은 이 환경에서 **불발이 실측**되었고, 아래 패턴은 **작동이 실측**되었습니다. 반드시 이 패턴을 씁니다:

```html
<button class="act" data-prompt="구체적 지시문">라벨 ↗</button>
<!-- 위젯 마지막에: -->
<script>
try {
  document.querySelectorAll('.act').forEach(function(b){
    b.addEventListener('click', function(){
      try { sendPrompt(b.getAttribute('data-prompt')); } catch(e) {}
    });
  });
} catch(e) {}
</script>
```

- 라벨은 동사형 + 끝에 `↗`. `data-prompt`는 붙여넣어도 그대로 실행 가능한 완결된 지시문으로 씁니다.
- 버튼이 통하지 않는 환경 대비로, 중요한 안건에는 복사용 지시문을 `<code>`로 병기할 수 있습니다.

## 4. 비유 시스템 (`.harness/reporting.json`)

| 키 | 의미 |
|---|---|
| `analogy` | 현재 비유(예: 공사장 — 하네스=안전 규칙과 감리, 커밋=벽돌 쌓고 사진). 사용자가 바꾸라고 할 때까지 고정 |
| `setAt` | 비유가 정해진 날짜 — 변경 시 함께 갱신 |
| `styleGuide` | 이 문서(또는 프로젝트별 상세 가이드) 경로 — 세션 훅이 매 세션 주입 |

## 5. 위젯 하드 룰

- 색·표면·글자는 CSS 변수만(차트 canvas와 상태칩 hex 제외), 바깥 배경 투명, `position:fixed` 금지
- 이모지 금지 → Tabler outline 아이콘(`ti-*`, `-filled` 금지, `aria-hidden`), 글자 두께 400/500만, 최소 11px
- 표 대신 flex 행 리스트, 데이터 상수는 사용 코드보다 먼저·한 `<script>` 안에, `<script>`는 문서 끝, 요소별 `try/catch`
- 렌더가 깨지면 같은 내용을 고쳐 새 title(`_v2`)로 전체 재렌더

## 6. 증거 연동

완료 보고의 **마지막 줄**은 `EVIDENCE_RECORDED: <docs/validation 경로>`(검증 있는 작업) 또는 `EVIDENCE_RECORDED: N/A(docs-only)`(순수 문서 작업)입니다. 상세 계약은 `AGENTS.md` Completion Standard를 따릅니다.
